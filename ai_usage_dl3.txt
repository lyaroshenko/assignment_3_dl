## Approach: a character-level BiLSTM tagger

The model reads the text one character at a time and labels each character as "part of a location" or "not". This is the simplest choice for this task, for three reasons:

- **No tokenizer and no label alignment.** Your labels are character spans like `(82, 88)`, so per-character labels come straight from them. A word-level model would need a tokenizer and code to map spans onto tokens.
- **No unknown words.** Ukrainian and Russian change word endings a lot (Київ / Києва / Києві). A word vocabulary would miss many of these forms. With characters, every input is known.
- **It sees capital letters and suffixes for free.** Capitals and endings like `-щині` or `-ській` are strong hints that a word is a place name. The model picks these up without any extra features.

For labels, I'd use **B / I / O** (Begin, Inside, Outside), applied per character. Plain inside/outside labels would be even simpler, but they would merge two locations that sit right next to each other. BIO is also the standard scheme, which makes it easier to defend.

## The metric in simple words

For each text, the gold locations and your predicted locations are cleaned (lowercased, digits and one-letter words removed) and turned into sets. A predicted string that exactly matches a gold string counts as correct (a true positive, TP). An extra prediction is a false positive (FP), and a missed location is a false negative (FN). These counts are added up over the **whole test set**, and then one precision, one recall and their F1 are computed. Only the strings matter, not where they appear in the text.

**Hidden detail:** the punctuation-removing line in `hard_processing` is missing the `f` in front of the string. So the pattern is the literal text `[{re.escape(string.punctuation)}]`. It only removes `. ( ) { }` and a few Latin letters. Commas, apostrophes, hyphens and quotes are **not** removed. From my test:

- `"вул. Солом'янська, 28"` becomes `"вул солом'янська,"` (the comma stays)
- `"Київ,"` becomes `"київ,"`, which does not match `"київ"`

So a span that includes a trailing comma or quote counts as wrong. When we turn predictions back into strings, we should trim leading and trailing punctuation.

## Strengths
1. **It doesn't depend on tokenization.** Only the final strings are compared, so a character model, a word model or a rule system are all scored the same way.
2. **It's fair when most texts have no locations.** Counts are pooled over all texts, so empty texts neither help nor hurt, and both missing locations and predicting too many are penalized.

## Weaknesses
1. **All or nothing.** "Шевченківському" against the gold "Шевченківському районі" gives 0 credit and is counted twice: 1 FP and 1 FN. Near-correct boundaries score the same as complete misses.
2. **Texts with many locations dominate.** Because counts are pooled, one post listing 10 towns weighs as much as 10 short posts. With only 477 test texts, the score is noisy. The punctuation bug above also adds noise unrelated to model quality.

## Edge cases
1. **Partial or wrong-form match:** "Київ" against the gold "Києва" scores 0, because nothing reduces words to their base form. You must copy the exact form from the text.
2. **Empty prediction and duplicates:** predicting `[]` for a text with no locations adds nothing to any count, so it's safe. Predicting the same city twice in one text counts once, because sets remove duplicates. A string that becomes empty after cleaning (e.g. `"28"` becomes `""`) is still a set element and can create a false positive.

## Complementary metrics
1. **Precision and recall reported separately.** They show whether the model misses locations or invents them. F1 alone hides this.
2. **Token-level or character-level F1 on the validation split.** It gives partial credit for overlapping spans, uses about 100k sentences instead of 26, and directly measures what our tagger predicts.

## Alternative target metric
**Partial-match entity F1** (like the "partial" mode of the SemEval-2013 NER evaluation): an overlapping prediction earns half credit (or credit proportional to word overlap) instead of zero. For real uses like geocoding or search, "Шевченківському" still points to the right district, so a nearly correct span is worth more than a miss. This metric reflects that and is less noisy on a small validation set.

## Local metric, exactly as Kaggle computes it

```python
import re
import string
from typing import List

def hard_processing(text):
    # NOTE: no f-prefix in the original -> this only strips . ( ) { } and some Latin letters,
    # NOT commas/apostrophes/hyphens. Kept as-is to match Kaggle's scorer.
    text = re.sub(r"[{re.escape(string.punctuation)}]", "", text)
    text = re.sub(r'\d', '', text)
    text = re.sub(r'\b\w\b\s?', '', text)
    text = re.sub(r'\s+', ' ', text).strip()
    return text.lower()

def comp_metric(y_true: List[List[str]], y_pred: List[List[str]]):
    assert len(y_true) == len(y_pred)
    tp, fp, fn, p = 0.0, 0.0, 0.0, 0.0
    for y_true_sample, y_pred_sample in zip(y_true, y_pred):
        y_true_sample = set(hard_processing(s) for s in y_true_sample)
        y_pred_sample = set(hard_processing(s) for s in y_pred_sample)
        tp += len(y_true_sample & y_pred_sample)
        fp += len(y_pred_sample - y_true_sample)
        fn += len(y_true_sample - y_pred_sample)
        p += len(y_true_sample)

    if tp + fp == 0:
        precision = 1.0 if p == 0 else 0.0
    else:
        precision = tp / (tp + fp)
    if tp + fn == 0:
        recall = 1.0 if p == 0 else 0.0
    else:
        recall = tp / (tp + fn)

    f1 = 0 if precision + recall == 0 else 2 * precision * recall / (precision + recall)
    return round(f1, 8)
```

## Cell 1: functions

```python
import re
from collections import Counter
import torch
from torch.utils.data import Dataset
from torch.nn.utils.rnn import pad_sequence

# (1) Tokenizer: words (apostrophes/hyphens inside a word allowed) or single punctuation/emoji
TOKEN_RE = re.compile(r"\w+(?:['’ʼ-]\w+)*|[^\w\s]")

def tokenize(text):
    return [(m.group(), m.start(), m.end()) for m in TOKEN_RE.finditer(text)]

# (2) Char spans -> BIO tags per token, and back
TAGS = ["O", "B-LOC", "I-LOC"]
TAG2ID = {t: i for i, t in enumerate(TAGS)}

def spans_to_bio(tokens, spans):
    tags = ["O"] * len(tokens)
    for s, e in spans:
        inside = [i for i, (_, ts, te) in enumerate(tokens) if ts < e and te > s]  # tokens overlapping the span
        for k, i in enumerate(inside):
            tags[i] = "B-LOC" if k == 0 else "I-LOC"
    return tags

def bio_to_spans(tokens, tags):
    spans, cur = [], None
    for (_, ts, te), tag in zip(tokens, tags):
        if tag == "B-LOC" or (tag == "I-LOC" and cur is None):   # an I without B also starts a span
            if cur: spans.append(tuple(cur))
            cur = [ts, te]
        elif tag == "I-LOC":
            cur[1] = te                                           # extend the current span
        else:
            if cur: spans.append(tuple(cur))
            cur = None
    if cur: spans.append(tuple(cur))
    return spans

# (3) Vocabulary
PAD, UNK = 0, 1

def build_vocab(texts, min_freq=2):
    counts = Counter(tok for t in texts for tok, _, _ in tokenize(t))
    itos = ["<pad>", "<unk>"] + [w for w, c in counts.items() if c >= min_freq]
    return {w: i for i, w in enumerate(itos)}

# (4) Dataset + collate
class NERDataset(Dataset):
    def __init__(self, texts, spans_list, vocab):
        self.texts, self.spans_list, self.vocab = list(texts), list(spans_list), vocab

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, i):
        tokens = tokenize(self.texts[i])
        ids = [self.vocab.get(tok, UNK) for tok, _, _ in tokens]
        tags = [TAG2ID[t] for t in spans_to_bio(tokens, self.spans_list[i])]
        return torch.tensor(ids), torch.tensor(tags)

def collate_fn(batch):
    ids, tags = zip(*batch)
    ids = pad_sequence(ids, batch_first=True, padding_value=PAD)
    tags = pad_sequence(tags, batch_first=True, padding_value=-100)  # -100 = ignored by CrossEntropyLoss
    return ids, tags, ids != PAD                                     # mask: True for real tokens
```

## How to explain it

- **Tokenizer:** `\w+(?:['’ʼ-]\w+)*` keeps "Солом'янська" and "Київ-Пасажирський" as one token, because Ukrainian apostrophes and hyphens are part of the word. Every other non-space character, such as punctuation or an emoji, becomes its own token. `finditer` gives each token's start and end position for free, which is how we turn predictions back into exact strings.
- **`spans_to_bio`:** a token belongs to a location if it **overlaps** the gold span. The first such token is tagged `B-LOC` and the rest `I-LOC`. Overlap rather than exact containment means a span boundary that falls inside a token still keeps the token.
- **`bio_to_spans`:** joins `B, I, I…` into one span from the first token's start to the last token's end. An `I-LOC` with no `B-LOC` before it is treated as the start of a new span, so a slightly wrong prediction isn't thrown away.
- **Vocabulary:** words seen at least twice in the **train split only**. Building it on train only keeps validation honest: unseen words there become `<unk>`, just as they will in the test set. `<pad>` = 0 and `<unk>` = 1.
- **Collate function:** pads each batch to its longest text. Tags are padded with `-100`, which `CrossEntropyLoss` ignores by default, so padding never affects the loss. The mask marks which positions are real tokens.

## What to check in the output

- **"spans recovered exactly"** should be close to 100%. Anything lower means some gold spans start or end inside a token.
- **"val `<unk>` rate"** shows how much the word vocabulary misses.
- **"vocab size"**: with min_freq=2 and capitals kept, it may be several hundred thousand words. That's fine on a GPU, but if the embedding table is too big for memory, raising `min_freq` to 3–5 is the simplest fix.

```python
# !pip install -q lightning wandb
import torch
import torch.nn as nn
import lightning as L
from lightning.pytorch.utilities import grad_norm
from torch.nn.utils.rnn import pack_padded_sequence, pad_packed_sequence

config = dict(
    rnn="lstm",          # "lstm" or "gru"
    emb_dim=128,
    hidden=256,
    num_layers=2,
    bidirectional=True,
    dropout=0.3,
    lr=1e-3,
    batch_size=256,
    max_epochs=10,
    patience=2,          # early stopping: epochs without val_f1 improvement
    grad_clip=1.0,
    val_size=20_000,     # val rows scored every epoch (the full 300k is too slow)
    seed=42,
)

class Tagger(L.LightningModule):
    def __init__(self, config, vocab_size, val_texts=None, val_spans=None):
        super().__init__()
        self.save_hyperparameters(ignore=["val_texts", "val_spans"])   # config + vocab_size -> W&B and checkpoint
        rnn_cls = nn.LSTM if config["rnn"] == "lstm" else nn.GRU
        self.emb = nn.Embedding(vocab_size, config["emb_dim"], padding_idx=PAD)
        self.rnn = rnn_cls(config["emb_dim"], config["hidden"], num_layers=config["num_layers"],
                           bidirectional=config["bidirectional"], batch_first=True,
                           dropout=config["dropout"] if config["num_layers"] > 1 else 0.0)
        out_dim = config["hidden"] * (2 if config["bidirectional"] else 1)
        self.drop = nn.Dropout(config["dropout"])
        self.head = nn.Linear(out_dim, len(TAGS))
        self.loss_fn = nn.CrossEntropyLoss(ignore_index=-100)        # -100 = padded positions
        self.val_texts, self.val_spans, self.val_preds = val_texts, val_spans, []

    def forward(self, ids, mask):
        x = self.emb(ids)
        packed = pack_padded_sequence(x, mask.sum(1).cpu(), batch_first=True, enforce_sorted=False)
        out, _ = self.rnn(packed)
        out, _ = pad_packed_sequence(out, batch_first=True, total_length=ids.size(1))
        return self.head(self.drop(out))                              # (batch, seq_len, 3)

    def _loss(self, logits, tags):
        return self.loss_fn(logits.reshape(-1, len(TAGS)), tags.reshape(-1))

    def training_step(self, batch, batch_idx):
        ids, tags, mask = batch
        loss = self._loss(self(ids, mask), tags)
        self.log("train_loss", loss, on_step=True, on_epoch=True, prog_bar=True)
        return loss

    def validation_step(self, batch, batch_idx):
        ids, tags, mask = batch
        logits = self(ids, mask)
        self.log("val_loss", self._loss(logits, tags), on_epoch=True, prog_bar=True)
        for row, m in zip(logits.argmax(-1), mask):
            self.val_preds.append(row[m].tolist())                    # predicted tag ids, padding removed

    def on_validation_epoch_end(self):
        if len(self.val_preds) == len(self.val_texts):                # skip Lightning's 2-batch sanity check
            y_true, y_pred = [], []
            for text, spans, tag_ids in zip(self.val_texts, self.val_spans, self.val_preds):
                pred_spans = bio_to_spans(tokenize(text), [TAGS[t] for t in tag_ids])
                y_true.append([text[s:e] for s, e in spans])
                y_pred.append([text[s:e] for s, e in pred_spans])
            self.log("val_f1", comp_metric(y_true, y_pred), prog_bar=True)
        self.val_preds.clear()

    def on_before_optimizer_step(self, optimizer):
        self.log_dict(grad_norm(self, norm_type=2))                   # per-layer + total grad norm, before clipping

    def configure_optimizers(self):
        return torch.optim.Adam(self.parameters(), lr=self.hparams.config["lr"])
```

## How to explain it

- **The RNN is chosen from the config:** `nn.LSTM` and `nn.GRU` take the same arguments, so one string switches between them. Dropout *between* RNN layers only works with 2 or more layers, which is why it's set to 0 for one layer. A separate `Dropout` before the output layer always applies.
- **Packing (`pack_padded_sequence`):** tells the RNN each sentence's real length, so it never reads padding. This matters most for the backward direction of a bidirectional RNN. Without packing, it would start from the padding at the end of each sentence instead of the last real word.
- **The loss ignores padding:** padded tags are `-100` (from `collate_fn`), the default `ignore_index` of `CrossEntropyLoss`. We flatten to (batch × tokens, 3) because the loss expects one row per token.
- **Competition metric on validation:** each val step stores its predicted tags. At the end of the epoch they are turned into spans, then strings, and scored with `comp_metric` against the gold strings. This works only because the val loader is **not shuffled**, so the stored predictions stay in the same order as `val_texts`.
- **Gradient norm:** `grad_norm` returns the L2 norm of every layer's gradient plus the total, and it's logged *before* clipping. On a healthy run, W&B should show the total norm staying roughly stable. Norms near zero mean gradients are vanishing. Spikes that hit the clip value often mean gradients are exploding (lower `lr`). If the embedding norm is much smaller than the LSTM norms, the signal isn't reaching the early layers.
- **Callbacks:** both watch `val_f1` with `mode="max"`. Early stopping ends training after `patience` epochs without improvement, and `ModelCheckpoint` keeps only the best epoch. `save_hyperparameters` stores the config in W&B and in the checkpoint, so `Tagger.load_from_checkpoint(path)` rebuilds the same model later.

## Cell 1: functions

```python
import json
import numpy as np
import pandas as pd

STRIP_CHARS = " ,;:!?\"'«»()—–-"   # the metric keeps commas/quotes (missing f-string), so trim them from span edges

def tags_to_spans(tokens, tags, mode="strict"):
    spans, cur = [], None
    for (_, ts, te), tag in zip(tokens, tags):
        if tag == "O":
            cur = None                                            # O closes the current entity
        elif cur is not None and (tag == "I-LOC" or mode == "loose"):
            cur[1] = te                                           # continue: I (strict) or any non-O (loose)
        elif tag == "B-LOC" or mode == "loose":
            cur = [ts, te]                                        # start a new entity
            spans.append(cur)
        # strict mode: I-LOC with no open entity is ignored
    return [tuple(s) for s in spans]

@torch.no_grad()
def predict_probs(model, texts, vocab, batch_size=256):
    model.eval()
    # 1) tokenize each full text, then cut its token list into lines (chunks)
    all_tokens, chunks = [], []                                   # chunk = (text index, first token, last token + 1)
    for i, text in enumerate(texts):
        tokens = tokenize(text)
        all_tokens.append(tokens)
        start = 0
        for j in range(1, len(tokens) + 1):
            if j == len(tokens) or "\n" in text[tokens[j - 1][2]:tokens[j][1]]:
                chunks.append((i, start, j))
                start = j
    # 2) run the model on chunks in batches and put the probabilities back per text
    probs = [np.zeros((len(t), len(TAGS)), dtype=np.float32) for t in all_tokens]
    for b in range(0, len(chunks), batch_size):
        batch = chunks[b:b + batch_size]
        ids = [torch.tensor([vocab.get(tok, UNK) for tok, _, _ in all_tokens[i][s:e]]) for i, s, e in batch]
        ids = pad_sequence(ids, batch_first=True, padding_value=PAD).to(model.device)
        p = model(ids, ids != PAD).softmax(-1).cpu().numpy()
        for row, (i, s, e) in zip(p, batch):
            probs[i][s:e] = row[:e - s]
    return all_tokens, probs                                      # probs[i]: (n_tokens_i, 3) for O, B-LOC, I-LOC

def probs_to_locations(texts, tokens_list, probs_list, mode="strict"):
    all_locs = []
    for text, tokens, probs in zip(texts, tokens_list, probs_list):
        tags = [TAGS[k] for k in probs.argmax(-1)]
        locs = [text[s:e].strip(STRIP_CHARS) for s, e in tags_to_spans(tokens, tags, mode)]
        all_locs.append(list(dict.fromkeys(l for l in locs if l)))   # drop empty, remove duplicates, keep order
    return all_locs

def make_submission(test_df, tokens_list, probs_list, mode="strict", path="submission.csv"):
    locs = probs_to_locations(test_df["text"], tokens_list, probs_list, mode)
    sub = pd.DataFrame({"text_id": test_df["text_id"],
                        "locations": [json.dumps(l, ensure_ascii=False) for l in locs]})
    sub.to_csv(path, index=False)
    return sub
```

## How to explain it

- **The two merge modes.** For tags `B I O I`, strict gives one entity and drops the lone `I` after `O`, while loose gives two entities. For `B B`, strict gives two entities and loose merges them into one. Strict trusts the model's B/I distinction. Loose forgives B/I mistakes but can glue two neighboring locations together. Which works better is an empirical question, and that's why the first cell compares them.
- **Splitting into lines without splitting the text.** We tokenize the whole text, so every token's position refers to the original text. Then we cut the token list wherever the gap between two tokens contains `\n`. Each line goes through the model separately, which matches the short single sentences it was trained on. Since positions always refer to the full text, `text[s:e]` gives the exact original string, which is what the metric needs.
- **Probabilities.** `softmax` over the 3 tags gives one row `[P(O), P(B), P(I)]` per token. The default decision is `argmax`. Later you can apply a threshold instead (e.g. call a token a location if `1 - P(O) > 0.3`). You can also average the probabilities of several models before decoding to ensemble them. They're saved to `test_probs.pkl` so you don't have to re-run the model for that.

```python
def load_fasttext(path, vocab, dim=300):
    needed = set(vocab) | {w.lower() for w in vocab}
    vecs = {}
    with gzip.open(path, "rt", encoding="utf-8") as f:
        next(f)                                                    # header line: "n_words dim"

            word, rest = line.rstrip().split(" ", 1)

    weights = np.random.normal(0, 0.1, (len(vocab), dim)).astype(np.float32)   # random for words not found

    hits = 0
    for w, i in vocab.items():
        v = vecs.get(w, vecs.get(w.lower()))                       # exact form first, then lowercase
        if v is not None:
            weights[i] = v
            hits += 1
    print(f"fastText vectors found for {hits / len(vocab):.1%} of vocab")
    return torch.tensor(weights)
```

```python
# ===================== EXPERIMENTS: model (replaces the earlier Tagger) =====================
class Tagger(L.LightningModule):
    def __init__(self, config, vocab_size, val_texts=None, val_spans=None, pretrained=None):
        super().__init__()
        self.save_hyperparameters(ignore=["val_texts", "val_spans", "pretrained"])
        rnn_cls = nn.LSTM if config["rnn"] == "lstm" else nn.GRU
        self.emb = nn.Embedding(vocab_size, config["emb_dim"], padding_idx=PAD)
        if pretrained is not None:
            self.emb.weight.data.copy_(pretrained)                        # (e) fastText init
        self.rnn = rnn_cls(config["emb_dim"], config["hidden"], num_layers=config["num_layers"],
                           bidirectional=config["bidirectional"], batch_first=True,
                           dropout=config["dropout"] if config["num_layers"] > 1 else 0.0)
        out_dim = config["hidden"] * (2 if config["bidirectional"] else 1)
        self.drop = nn.Dropout(config["dropout"])
        self.head = nn.Linear(out_dim, len(TAGS))
        self.loss_fn = nn.CrossEntropyLoss(ignore_index=-100)
        self.val_texts, self.val_spans, self.val_preds = val_texts, val_spans, []

    def forward(self, ids, mask):
        x = self.emb(ids)
        packed = pack_padded_sequence(x, mask.sum(1).cpu(), batch_first=True, enforce_sorted=False)
        out, _ = self.rnn(packed)
        out, _ = pad_packed_sequence(out, batch_first=True, total_length=ids.size(1))
        return self.head(self.drop(out))

    def _loss(self, logits, tags):
        return self.loss_fn(logits.reshape(-1, len(TAGS)), tags.reshape(-1))

    def training_step(self, batch, batch_idx):
        ids, tags, mask = batch
        loss = self._loss(self(ids, mask), tags)
        self.log("train_loss", loss, on_step=True, on_epoch=True, prog_bar=True)
        return loss

    def validation_step(self, batch, batch_idx):
        ids, tags, mask = batch
        logits = self(ids, mask)
        self.log("val_loss", self._loss(logits, tags), on_epoch=True, prog_bar=True)
        for row, m in zip(logits.argmax(-1), mask):
            self.val_preds.append(row[m].tolist())

    def on_validation_epoch_end(self):
        if self.val_texts is not None and len(self.val_preds) == len(self.val_texts):
            y_true, y_pred = [], []
            for text, spans, tag_ids in zip(self.val_texts, self.val_spans, self.val_preds):
                pred_spans = bio_to_spans(tokenize(text), [TAGS[t] for t in tag_ids])
                y_true.append([text[s:e] for s, e in spans])
                y_pred.append([text[s:e] for s, e in pred_spans])
            self.log("val_f1", comp_metric(y_true, y_pred), prog_bar=True)
        self.val_preds.clear()

    def on_before_optimizer_step(self, optimizer):
        self.log_dict(grad_norm(self, norm_type=2))

    def configure_optimizers(self):
        cfg = self.hparams.config
        if cfg.get("optimizer", "adam") == "adam":
            return torch.optim.Adam(self.parameters(), lr=cfg["lr"])
        opt = torch.optim.AdamW(self.parameters(), lr=cfg["lr"], weight_decay=cfg.get("weight_decay", 0.01))   # (d)
        sched = torch.optim.lr_scheduler.OneCycleLR(opt, max_lr=cfg["lr"],
                                                    total_steps=self.trainer.estimated_stepping_batches)
        return {"optimizer": opt, "lr_scheduler": {"scheduler": sched, "interval": "step"}}
```

```python
              for m in ("strict", "loose")}
```

```python
def load_fasttext(path, vocab, dim=300):
    needed = set(vocab) | {w.lower() for w in vocab}
    vecs = {}
    with gzip.open(path, "rt", encoding="utf-8") as f:
        next(f)                                                    # header line: "n_words dim"
        for line in f:
            word, rest = line.rstrip().split(" ", 1)
            if word in needed:
                vecs[word] = np.asarray(rest.split(" "), dtype=np.float32)
    weights = np.random.normal(0, 0.1, (len(vocab), dim)).astype(np.float32)
    weights[PAD] = 0
    hits = 0
    for w, i in vocab.items():
        v = vecs.get(w, vecs.get(w.lower()))                       # exact form first, then lowercase
        if v is not None:
            weights[i] = v
            hits += 1
    return torch.tensor(weights), hits / len(vocab)
```

## What the results show

**Validation F1 (the big, reliable score).** Earlier I said differences under about 0.005 are within noise for a single seed. By that rule:

- **Bidirectional matters most.** The forward-only model loses 0.020 (0.890 vs 0.910), the only clearly bad change. A location often depends on the word *after* it (e.g. "Орловской **областях**"), and a forward-only model can't see that.
- **fastText helps a little (+0.005), right at the noise limit.** It also got there fastest: its best epoch was epoch 1, against epoch 3 for the baseline. Starting from pretrained word vectors speeds up learning. The vectors covered 77% of the vocabulary.
- **GRU, BPE and AdamW + OneCycle are about the same as the baseline** (0.905–0.910). BPE is notable because its embedding table is about 12× smaller (30k subwords vs ~375k words) and it still scores about the same. OneCycle needed more epochs for no gain.
- **1 layer is slightly worse (−0.010).**

**`labeling_sample` F1 (26 test-like texts).** Scores range from 0.548 to 0.657, much lower than validation, as the EDA predicted. The ranking also differs: 1-layer is best here but second-worst on validation. With only ~32 gold locations, one location more or less shifts F1 by about 0.03.
